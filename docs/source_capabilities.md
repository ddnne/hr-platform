# NARの取得条件と実測 — 2026-09-30

## 現在の結論

- **Macから少数の公式ZIP・HTMLサンプルを取得できた。** HTTP200、原本保存、UTF-8 BOMの解析、異なる取得時点の履歴・as-ofを実測した。内容が同じでも別の観測を残す。
- **CloudflareからのNAR取得は未成功。** 2026-09-29の2回はHTTP404。同じURL・研究UA・AcceptでのMac対照は200だったが、時刻差があり原因は未確定。恒久的な拒否や申請必須とは断定しない。
- 通常の公開ZIP取得に登録・申請が必須という記載は、確認した説明書にはない。定期自動取得・私的な継続クラウド保存への条件適用は未解決。少数サンプルの成功を無条件の許諾と扱わない。
- ユーザーは問い合わせを前提にせず低頻度・少数サンプルで研究を進める範囲を承認済み。登録・問い合わせ送信は人が行う。現時点の新たな依頼はない。[人に依頼する範囲](human_actions.md)

## 取得・保存の実装境界

| 能力 | 状態 |
|---|---|
| capture_mode | `poll_snapshot`。観測履歴は自前で追記する |
| NAR公式のupstream_history / backfill | 全更新履歴の配布は未検証。第三者の履歴表示とは区別する |
| 頻度 | Macの有限計画は要求間隔を全種共通で120秒以上に制限。常時収集ではない |
| ZIP | 複数競走・券種を含む一配布物を一度取得して内部で分配。買い目のゼロ・欠落・範囲表示を区別 |
| 時刻 | 取得開始・ヘッダー受信・本文受信・原本/receipt保存・索引登録・解析・利用可能時刻を分離 |
| source_updated_at | 公式CSVの市場更新時刻は不明なのでnull。ファイル名UNIX時刻や取得時刻で代用しない |
| 同値と再配送 | 別取得は同じ本体でも別観測。同一イベントの再配送は通信・観測・判断を増やさない |
| 月次 | `monthly_odds`で原本・取得receipt・`FINAL_ONLY`検査を保存。観測・Paperへ登録せず、月次要求は24時間以上空ける。実ファイルの取得成功は未確認 |
| CloudflareからNARへの直接取得 | 失敗2件、成功ZIP/観測0件。収集false、空枠、Cronなし、公開URL/previewなしで停止中。Mac原本のクラウド取込み・解析実績はstatusへ別記 |
| 公開境界 | 原本・実データ・詳細出力・台帳・SecretsをGit/CI/PRに出さない |

Macでは承認済みの有限サンプル経路を使用し、Cloudflareの停止状態を変えない。`collect-sample`と`paper-session`は同じ取得処理を使い、同じprivate rootで間隔・停止状態を共有する。リダイレクトや自動再試行は行わず、拒否・CAPTCHAで停止、429はRetry-After以上待機する。未取得期間を後の断面で埋めない。[実データ手順](real_data_runbook.md)

## 状態・払戻の実物確認

- 公式単複ページの最終見出し、競走除外、日付のない`HH:MM現在`を確認。最後の表示は日付が確定できないため`source_updated_at=null`。空欄から発売中や出走有効を推定しない。
- [結果・払戻の説明](https://www.keiba.go.jp/beginner/step6.html)は確定後の100円当たり払戻を案内し、除外馬を含む馬番号の組合せは全額返還とする。枠式には別条件がある。
- [異常時の表記説明](https://www.keiba.go.jp/beginner/step2.html)では、発売前の出走取消、主に発売後の競走除外と返還、出走済みの競走中止と返還なしを区別している。
- 成績実例で通常馬連・三連複払戻と除外返還を正規化した。数値着順は掲載組番の整合確認に使い、払戻額は計算しない。同着・特払い・不成立・枠式の自動適合は未完了。重勝式用の取消・除外馬番欄を通常馬連の返還根拠へ流用しない。

取得・モデル・Paper・Cloudflareの進捗は [status.md](status.md)。過去の「未取得」「人の取得待ち」はGit履歴に保持し、現在の停止条件とはしない。

### 0.0表示の意味

2026-09-30に確認した[楽天競馬の公式FAQ](https://keiba.faq.rakuten.net/detail/000017065)は、0.0表示の理由として無投票と競走除外時の一時表示を挙げている。無投票という仮説の参考にはなるが、NAR配布CSVの状態コードを定義する資料ではない。保存したNAR断面で0.0から正の値への変化は確認したものの、個々の0.0の原因は未確定。確率0・無限大の倍率・有効な数値オッズへ置換せず、元の表示を保持して不明値として扱う。

同日の追加研究では、ユーザーの提案に従い、出走状態と全組合せが確認できる断面で「明示的な0.0は無投票」と仮定する感度分析を分けて実行した。この場合だけ、その組合せの市場投票比率への寄与を0に置き、正の倍率からの逆数と合わせて正規化する。真の的中確率0という扱いではない。欠落した組合せ・空欄・レンジを0にせず、原本・既存の正規化結果・Paper判断も変更しない。提供元による意味の確認と、条件付きの研究結果を区別する。

## 第三者履歴の採用取りやめと削除（2026-09-30）

[keibaoddsの地方競馬画面](https://keibaodds.com/nar)と公開JSONで中間時刻ラベルを確認したが、組合せ券種の人気順履歴は各時点50組に限られる例だった。取得コードは応答を切り詰めず保存しており、配信応答そのものに残りの組合せがなかった。公開クライアントの「全件」は受信済みの全件を表示するだけで、追加要求しない。`page`は競走一覧、`display_times`は時点数の指定で、確認したコードに買い目の続き・全量を要求する指定はなかった。

競走を一つに絞った公開要求でも、9頭の馬単は必要72組に対し50組だった。12頭なら馬単132組・三連単1,320組が必要で、全同時分布の比較に不足する。提供元の内部にも全量がない、別経路もないとまでは断定していない。

ユーザーの「全組合せが揃うデータセットだけを使う」「不完全データを削除する」という指示に従い、この取得先を採用対象から外した。専用Worker `hr-platform-dev-archive` の取得を無効にしてCronを空にし、同ソースの停止フラグを保持する。R2の専用`archive/`、D1の専用取得履歴・待ち一覧、ローカルの取得データと派生分析を削除した。過去の収集承認や手順を根拠に再開しない。

今後は出走馬に対する対象・参照券種の全組合せがあることを確認して採用する。三連単からの比較には全三連単を要求する。欠落を0・次の断面・最終値で埋めず、明示的な0.0を無投票と仮定する研究とは分ける。全量の過去中間履歴を取得できる公開経路は未確保で、公式当日ZIPの全量断面を時刻付きで保存する方針を優先する。

元の取得・解析コード、専用のWrangler設定・テスト・ビルド処理も撤去した。配置済みWorkerは無効・Cronなしを維持する。適用済みmigrationはスキーマの履歴として残す。実データの削除範囲・検証結果は[状態報告](status.md)へ記録する。NAR公式の別Worker・原本・Paper台帳は今回の削除対象に含めない。

地方を主対象にする最新の指示に従い、全場の当日断面を約2分ごとに保存する準備を進める。[一日計画と競走別照会](day_collection.md)は共通のローカル取得処理を使う。約2分は更新周期であり、投票締切・レース前の最終更新の2分前に配信される保証は確認できない。CSVに市場更新時刻がなく、受信時刻やファイル名で遅延上限を証明しない。

### 南関東公式の全組合せの実物確認

2026-09-30の終了済み9頭立て1競走で、公開リンクから辿った5ページを各1回、120秒以上空けてMacで取得した。5件ともHTTP200。共通のHTTP入口とStoreの原本保存を使い、取得証跡と解析結果は非公開で保存した。Paper入力には追加していない。次の直前比較用に、同じ取得処理を使う[少数の固定時点取得](day_collection.md#南関東公式の少数時点比較)を実装したが、開催中の実行はまだ行っていない。

| 券種 | 必要な組合せ | 取得・NAR保存値との一致 |
|---|---:|---:|
| 単勝 / 複勝 | 各9 | 各9 |
| 枠複 / 枠単 | 29 / 57 | 29 / 57 |
| 馬複 / ワイド | 各36 | 各36 |
| 馬単 | 72 | 72 |
| 三連複 | 84 | 84 |
| 三連単 | 504 | 504 |

9券種の全836組が揃い、複勝・ワイドのレンジを含め保存済みNARの値と一致した。三連単は1回のHTML応答に504組全てが入っていた。三連複は軸馬別の表示に同じ組番が3回現れるため、値の一致を確かめて84組として数えた。枠式は同枠に2頭いる場合の組合せを含む。不可能な同一馬の組合せ等の「－」は必要な組合せの欠落や無投票0として扱っていない。

確認した表示は**最終オッズ**であり、過去の中間履歴・直前配信・実行可能な収益バックテストの証拠ではない。各ページの取得時刻を保持し、複数ページ間の同期を推定しない。提供元更新時刻はnull。取消・発売前・0表示・他の頭数の解析は未適合で、Cloudflare取得も未実行。別途取得したrobots.txtは通常の「URLが存在しない」404ページだった。取得証跡を保持し、取得許諾の根拠や拒否の回避には使わない。

次の開催中に、事前に選ぶ1競走・1ページの少数断面で、2分前付近から1分前付近の価格変化とNAR ZIPとの差を測る。公開値の変化、各経路で最初に観測した時刻、締切前の利用可能性を分ける。更新時刻が不明なまま真の配信遅延を算出せず、締切後に受け取った値を判断入力へ戻さない。全場を一度で取得できるNAR ZIPは継続候補とし、南関東公式への取得先統一は直前実測後に判断する。

[地方競馬DATAの時系列オッズViewer2案内](https://saikyo.k-ba.com/members/chihou/soft.cgi?page=soft_jikeiretsu)では、地方競馬の時系列表示を確認できた。ただし、掲載対象は単勝・複勝・枠連・馬連で、対応OSはWindows、データ会員は有料。必要な馬単・三連単の全時系列を、この案内から確認できない。購入データ・Windowsを使わない今回の条件にも合わないため採用しない。登録・取得・問い合わせは行っていない。

公開検索で見つからないことを、全量履歴が存在しない証明にはしない。新たに採用できる公開経路は未確保のままで、当日の公式断面を保存する方針を維持する。
