# 保存履歴からのCloudflare研究計算

非公開の独立Workerで、共通の`research_suite`を使う。既存の競馬収集・3方式の実時間Paperと別の処理で、HTTPは404を返す。R2/D1アクセスは`CloudHistory`の共通入口だけを使う。

## 初版の範囲

- NAR平地の保存済み中間オッズを、指定した固定as-ofで再読出しする。解析の`available_at`が後のデータとFINAL_ONLYは入力に使わない。
- 戦略設定・計算コード・依存lock・Worker互換設定を版に対応づける。同じ登録版の変更は拒否する。設定を変える場合は新しい版を登録する。
- 91案を共通数理で計算し、市場欠落や不適格は該当系列のINPUT_EXCLUDEDとして残す。提供元更新時刻が不明な別観測を混合しない。原照会結果も保持する。
- jobは登録版・競走・as-ofで一意。同じjobの再配送で完了済み結果を重複追加しない。中断した計算は同じjobで再試行する。1起動で1jobを処理し、中断は設定したリースと試行数で扱う。
- 結果はR2へ保存後、D1の文実行時刻で公開する。遅れて得た結果を過去へ戻さない。結果・固定入力・処理開始・公開時刻を再読出しできる。

候補計算と事後評価を別に保存する。元の結果の`settlement_status=NOT_EVALUATED`は変更せず、事後評価を読む。日額上限の適用、登録前の過去期間の一括投入、追加3競技のCloud入力接続は次の作業。`timing_qualified=false`・`daily_budget_applied=false`の事後研究を、実時間購入や収益性の成功と解釈しない。

## 準備と利用

`scripts/prepare_backtest_worker.py --out private/<新規build>`で、公開ソースだけの新規buildを作る。既定ではCron空・計算無効・公開無効。設定値は`configs/cloud-research.json`、保存用の追加表は`migrations/0011_cloud_research.sql`。

承認済みの非公開環境への配置後、service bindingの`research`へJSONを渡す。

1. `register`: `version`、既存の`base`、8系列の`configs`を登録する。
2. `enqueue`: 返された`bundle_id`、`race_id`、固定時点`at`で保存履歴の計算を予約する。
3. `jobs`: 登録版のjobを一覧する。`after`に最後のjob IDを渡して続きが読める。
4. `result`: `job_id`と照会時点`at`で公開済み結果を読む。
5. `final_prices`: `race_id`、`markets`、事後の照会時点`at`で、保存済みの`FINAL_ONLY`価格だけを読む。原観測・解析版・利用可能時刻を保持し、不足した市場は`missing_markets`へ残す。中間値や公式払戻から補わない。この照会は判断入力のas-ofと別で、公式精算や価格の保存完了を保証しない。
6. `evaluate`: `job_id`、証跡の照会時点`at`で、固定済み候補を公式払戻と最終価格に対応づける。モデルの再計算やPaper台帳への書込みは行わない。評価コード版・元結果・払戻解析版・最終価格解析版が同じなら既存評価を返す。証跡が増えた場合は別評価をR2へ保存し、`migrations/0012_cloud_research_evaluations.sql`の索引へ公開する。
7. `activate`: 現在のengineの`bundle_id`と開始日`from_date`（YYYYMMDD）を有効化する。同じ登録を再送してもカーソルや予約を増やさない。
8. `evaluation`: `evaluation_id`、照会時点`at`で保存済み評価を読む。評価自体のD1公開時刻を越えて過去へ返さない。証跡の時点と評価の利用可能時刻は別に保持する。

事後評価は戦略ごとに購入競走数・購入点数・的中競走数・的中点数・掛金・払戻・返還・損益を返す。表示・最終オッズは掛金加重平均で、複勝・ワイドのレンジは下限と上限を別に保持する。最終価格の支持集合が購入時と違う、価格が欠測などの場合は平均最終オッズをnullにする。公式払戻の確認と価格の確認は独立している。

NARの通常競走は、全頭の完走・上位3着・購入前の枠情報・券種別の公開払戻表を照合し、整合する券種だけ精算する。取消・除外・中止がある場合は既存の馬連・三連複の確認範囲を使い、他券種へ返還規則を広げない。未精算の購入が一つでもあれば、その戦略の総払戻・総損益・的中数をnullとする。入力除外は正常な見送りと分け、評価可能競走数に含めない。取得・解析の予約は既存のままで、このWorkerは提供元へアクセスしない。

成績表・買い目・詳細な実験結果はチャットと非公開Cloudflare保存だけに残す。GitHub、CIログ、Artifacts、PRへ掲載しない。

保存済みの公式月次ZIPは、既存の原本解析担当が`FINAL_ONLY`として索引化する。日次とCSV行の解析を共用し、月次の複数CSV・ヘッダーだけの空パート・月と競走日付・重複競走を検査する。月次には別の解析版を使い、既存の日次解析を一律に再実行しない。中間値と出走・払戻情報の解析を優先し、その空きで月次を処理する。新たな観測を作らず、解析結果の利用可能時刻は索引公開時に付ける。月次から中間推移や実時間の購入機会を復元しない。

有効化したCronが予約済みjobを処理するため、端末を常時動かす必要はない。実環境での配置・計算・時間・使用量は、実行後に`docs/status.md`へ記録する。

## 毎日の研究予約と評価

`AUTO_RESEARCH_ENABLED=true`と既存のCronを設定すると、保存済み番組から当日の地方平地を選び、有効な登録版の判断時点を到来前に予約する。既存Paperの間引き済み予定を分析対象の全体とは扱わない。開始日の前、判断時点を過ぎた競走、結果あり、ばんえい、出走数不一致は新規予約しない。約定や投票締切の実測を伴わないため、発走からの設定オフセットを受付締切と呼ばない。

調整値は`configs/cloud-research.json`に置く。将来予約の窓、1回の予約数、待ち行列の上限を守る。番組の時刻変更は未開始かつ判断時点が未来の自動予約だけを置き換え、旧計画をR2に残す。元の時刻へ戻った場合も同じ論理jobを復元する。D1のリース所有者を更新条件へ入れ、遅れて再開した旧担当が新予定を巻き戻せないようにする。実行はWorker時計とD1時計の両方で判断時点の到来を確認する。

予約・候補計算・事後評価は独立して進む。入力欠測や古さは既存の判定で除外し、後から得た断面で置き換えない。完了済みjobを順に事後評価し、同じ証跡なら既存評価を返す。失敗したjobが後続の評価を止めないようカーソルを先に進める。評価の巡回時間は完了job数と設定間隔に依存し、全件即時の精算を保証しない。

追加表は`migrations/0013_cloud_research_automatic.sql`。新しいengineへの切替時は、旧engineの未完了jobと将来の自動予約を確認する。公開経路や収集担当の予約は変更しない。91案の自動研究は日額上限未適用の事後比較で、既存の実時間Paper台帳を増やさない。配置後のCronによる予約・計算・評価の実測は`docs/status.md`で区別する。
