# 中央競馬の取得準備

地方競馬の既存収集を保ちながら、JRA公式の匿名オッズ画面を追加候補として確認している。中央専用のTeam-Nave、購入データ、Windows依存のSDKは使わない。

## 実ファイルで確認したこと

2026年10月3日の公式開催選択には東京・京都が掲載されていた。公式画面のリンクにある`cname`を、`/JRADB/accessO.html`の匿名フォームへPOSTし、東京1Rの全8券種を確認した。ログイン・Cookie保存・登録・問い合わせ・リダイレクト追従は行っていない。最初のGETは301で失敗し、公式のPOST導線とは区別した。有限調査の取得は60秒以上空け、拒否・CAPTCHAでは停止、429ではRetry-Afterを含む待機を適用する。

15頭の出走情報から支持集合を照合した。枠連は1頭だけの枠の同枠を除いて35組。対角など成立しない組の空欄は欠測に数えず、成立する組の未掲載は欠測として扱う。「票数なし」は明示された非数値で、数値オッズや確率0へ変換しない。

初回サンプルは全て本文に最終オッズと表示されている。レース前の判断、過去の中間推移、締切直前の実行可能性の検証には使わない。三連単は1本文599,774 bytesで、今回の7オッズ本文は既存の2MiB取得上限内だった。18頭の最大本文サイズは未実測。

## 解析コードと公開条件

`workers/jra.ts`は取得を行わない純粋なパーサー。組合せ、オッズの数値・幅・明示0、全量確認、番組時計を既存処理と共用する。`configs/jra-source.json`に場名・上限・HTMLクラス・文字コードを置いた。競走識別の一致、競走名・種別・コースの障害判定、枠のrowspanを確認する。未知の表示時刻はUNKNOWN、提供元更新・公開時刻はnullのまま保持する。

Shift JISは既存のローカルWorker実行系で合成文字を復号できた。保存済み7本文を実コードで解析し、全8市場の組数・最終表示・平地情報を照合した。これは初回の保存本文の検証で、Cloudflareの実取得・保存は後段で別に確認した。

[公式サイト利用条件](https://www.jra.go.jp/use/)と[robots.txt](https://www.jra.go.jp/robots.txt)を確認した。取得した利用条件には、オッズの自動取得頻度・長期保存を個別に規定した説明は確認できていない。robotsの取得許可を、契約上の利用許可や頻度の保証として扱わない。原本・詳細な解析は非公開に保ち、規約の変更や拒否を回避しない。

## 次の作業

既存の共通HTTP・原本保存・履歴入口へJRAの有限取得を接続した。公開設定では取得無効を維持し、既存の非公開環境で個別に予約する。単複ページの保存済み出走情報を他ページの解析へ渡し、元の取得開始時点に利用可能だった解析版だけを参照する。同値の再観測、再配送、保存原本の再解析を区別する。

JRAの待機と停止は既存3競技と別の提供元キーで管理する。有限取得は設定した60秒間隔・同時1要求とし、原本公開前に受信後の待機を保存する。拒否・CAPTCHAは停止、429はRetry-Afterを保つ。開催・番組の日次処理へ接続した。公式の開催リンクでは状態桁と場番号を分け、元の導線を変更せず保持する。状態桁の意味を発売状態へ置き換えず、日・場・競走を照合し、保存した券種リンクを保持する。日本語の時分・HH:mmの発走予定を共通時計へ変換し、元の表示も保存する。解析版を分け、後で解析した時計を過去のas-ofへ入れない。受付締切はnullのまま分ける。発走済・中止・未知の表示から時計を補わない。JRAの日次actionも同時1件とし、他3競技の並列Cronは継続する。中央のオッズ・結果の自動タスクはまだ生成しない。本文読出しの一時失敗は同じ解析版で再試行できる。

Cloudflareから有限予約による取得・保存・解析・履歴照会を確認した。端末接続を閉じていた間の実行、同値の別観測、原本本体の重複排除、古いas-ofの不変も確認した。詳細な実測記録は非公開に保持する。初回は最終表示で、その後に中間表示の有限取得も確認した。中間表示の全市場を読み戻し、複数時点の履歴・出走情報による全組合せ検査・旧as-ofの不変を照合した。券種間の同時更新は保証しない。

開催・番組の日次接続をCloudflareで実測する。全市場の定常巡回と締切前の鮮度を実測し、全場の継続収集・結果取得へ進む。中央の当日全競走収集やPaper適合を達成したとは報告しない。複数サイトの冗長化は後回しにする。
