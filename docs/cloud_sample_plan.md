# Cloudflareでの2回限定サンプル取得案

状態：実装・ローカル検証段階。未デプロイ・未実行。

## 実行範囲

- 対象は既存の `hr-platform-dev-ingestion`、D1 `hr-platform-dev-index`、非公開R2 `hr-platform-dev-private` のみ。
- 2026-09-30 17:00 / 17:05 JST（08:00 / 08:05 UTC）に、公式の当日オッズZIPを各1回、最大2回取得する案。間隔は5分。期日を過ぎた場合は実行せず、過去分の取得と扱わない。
- `CAPTURE_SLOTS_JSON` にこの二時刻のUTCミリ秒を指定する。本番scheduled入口は空・不正計画・予定外・予定前・120秒超の遅延では新規HTTP取得しない。保存済み原本の索引修復は、承認済み枠に限って期限後も追加取得なしで行える。
- 同一イベント再配送は既存のイベントIDで冪等化。別時刻の同じ内容は別観測として保存する。403・CAPTCHAは停止、429は既存の待機条件を守り、別経路や追加枠による回収はしない。
- 初回有効化時のみ両取得スイッチをtrueとし、5分Cronを設定する。指定日時以外は取得しない。終了確認後にスイッチfalse・Cron空へ戻す。戻す作業が遅れても、有限の二枠を超えて取得しない。
- 原本・manifest・観測を既存の非公開保存先に残す。最大圧縮量は既存上限16MiB×2。実バイト数、取得/処理時間、保存・照会件数を記録する。新規契約・プラン変更・公開範囲の変更は含めない。

## 完了の確認

1. 遠隔のWorker設定・対象リソースを直前に照合する。
2. 両枠の試行を取得ログで確認する。欠測・拒否もそのまま報告する。
3. 成功時は両manifestと原本を再読出しし、別観測として保存されていることを確認する。
4. ローカル解析へ渡した場合のavailable_atは実際の解析完了時刻とする。取得時点へ遡らせない。
5. Cloudflare上の取得・保存と、ローカルのモデル計算を分けて記録する。二回の成功を無期限の継続稼働やPaper成功と呼ばない。

## 承認の境界

ユーザーは問い合わせなし・低頻度の少数サンプル取得を認めている。一方、最初の指示ではデプロイ等を指定環境・承認範囲内に限定している。これまでのCloudflare環境は停止状態の準備であり、上記の有限枠による実収集への切替を確認対象とする。通常のコード変更・レビュー・マージの承認は求めない。

この案はNARから個別許可を得たという意味ではない。登録・申請・メール・問い合わせを代行することも含めない。

参考：[Cloudflare scheduled handler](https://developers.cloudflare.com/workers/runtime-apis/handlers/scheduled/)。scheduledTimeは予定時刻であり、実受信時刻とは別に保存する。
