# 人にお願いする対応

## 現在の依頼 — 2026-10-02

**現在、人への依頼はない。** ユーザーから「データの取得日時の予約は自律的に進めて良い」と明示承認を受けた。既存Cloudflare収集担当への取得日時予約・見直しを自律実行し、外部サービスへの会員登録・利用申請・メールは引き続き人が行う。

園田6Rの研究用払戻1ページは、承認後に現在の取得枠・停止状態・入力保護範囲を再照合し、17:40に予約した。先の自動承認審査の拒否で未実行だった件は解消。予約の完了であり、実際の取得・精算はこれから確認する。

10月1日にユーザーからCloudflareでの新規取得を明示承認された。同じ公式URL・研究UAで17:38の単発取得がHTTP200となり、原本保存・読み戻し・自動解析を確認した。続いてCloudflare内のタイマーによる日次取得を開始し、Macの重複収集を終了した。10月2日の公式エラーHTMLによる停止は、保存証跡の確認後に既存承認内で一度解除し、同経路でのZIP取得復帰を確認した。外部サービスへの会員登録・申請・問い合わせ・新規契約は行っていない。[実測](status.md#cloudflare上で実測したこと)

 人気上位50組に限られる第三者履歴は、最新のユーザー指示に従って収集を停止し、取得データと派生出力を削除した。過去の再開承認・手順は失効しており、この取得先の再開やデータ復元は行わない。[削除範囲と結果](status.md#cloudflare上で実測したこと)

全組合せが揃う公式断面の有限取得と、条件に適合する過去履歴の取得経路確認を進める。通常開発、日本語PR、独立レビュー、CI、マージは自律的に行う。登録・問い合わせや追加契約の依頼はない。欠けたオッズや過去の利用可能時刻は補完しない。

9月29日のCloudflareからの2回の404の原因は未確定だが、10月1日は同じ経路で取得できた。通常ダウンロードに登録・申請が必須という根拠は得られていない。現在の根拠と残点は [取得条件](source_capabilities.md) にまとめる。

次の場合は、必要な判断・根拠・費用・対象を可能な範囲でまとめて人へ提示する。

- 登録、申請、メール、問い合わせ送信が必要になった場合。文面は準備するが、送信は人が行う。
- 新規契約・プラン変更・公開設定変更など、既存の承認範囲を超える場合。
- 提供元の拒否や未解決条件により、現在の取得方法を続けられない場合。停止を解除したり経路を切り替えて回避しない。

最初のZIP取得や通常のコードレビューを人の必須作業にする以前の記述は撤回済み。経緯はGit履歴に保持する。

件名：公開データダウンロード機能の自動取得・非公開保存の利用条件について

地方競馬の個人研究のため、公開されている当日オッズZIPを、開催中に約2分に1回、Cloudflare Workersから取得し、非公開のR2へ取得時刻とともに保存することを検討しています。複数競走・券種を含むZIPは一度だけ取得して内部で分配します。データ・原本・買い目の公開や再配布、商用提供、実投票は行いません。アクセス拒否やCAPTCHAでは停止し、429では指定時間待機します。

1. 説明書の推奨取得頻度とrobots.txtのDataDownloadへのDisallowは、この用途にどう適用されますか。自動取得できる正式な経路・条件があれば教えてください。
2. 原本と観測履歴を非公開クラウドへ保存し、私的に分析する用途について、必要な手続き、保存期間などの条件はありますか。
