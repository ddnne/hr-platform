# Cloudflareでの当日収集

既存の`hr-platform-dev-ingestion`、`hr-platform-dev-research`、非公開R2・D1を使う。設定の作成と実稼働は区別し、現在の実測は[status.md](status.md)へ記す。

## 処理

- 収集用のDurable Objectを提供元に一つ置く。Cloudflareのalarmが次の取得を起動し、MacやCodexの常時起動に依存しない。
- 日付が変わると最初に当日のレース情報ZIPを取得する。全場のレース一覧・出走情報・結果・払戻表示を、既存CSVパーサーで保存する。
- 原本、取得試行、観測、解析版をR2・D1に保存する。同値の再観測も残し、同じイベントの再配送は再取得しない。
- 収集DOは取得・原本保存だけを行う。研究Workerの別Cronが未解析原本をD1から1件ずつ選ぶため、解析・モデルの失敗や長い待機で取得を止めない。レース情報、次に新しいオッズを優先し、過去データの移送で直近の入力を待たせない。失敗した解析の原本は残る。
- オッズとレース情報は一つのHTTP入口・停止/待機状態を使う。403等の拒否・CAPTCHA・HTML異常応答で停止し、429ではRetry-After以上待つ。停止を定期処理から解除しない。
- alarmが取得窓を過ぎたら欠測を記録する。後の取得を停止期間の過去断面として扱わない。

## 設定

取得間隔・有効な取得窓は`configs/collection.json`、時間帯・レース情報の再取得間隔・URL・HTTPの上限は`configs/cloud-collection.json`に置く。現案は毎日07:00〜23:00 JST、要求完了から120秒以上空ける。30分ごとのレース情報取得はオッズ取得の1回分を使うため、その前後のオッズ間隔は通常より長くなる。全更新や厳密な2分周期を保証する設定ではない。

`DAILY_COLLECTION_ENABLED`、`COLLECTION_ENABLED`、`SOURCE_APPROVED`が全てtrueの場合だけ日次収集する。収集のCronは毎時の起動確認に使い、同じDurable Objectのalarmが既にあれば重複起動しない。研究Workerは毎分のCronで未解析原本を確認し、同じ観測・解析版の同時処理をD1のリースで抑える。既存の有限サンプルモードは日次スイッチfalseのときにだけ使う。公開HTTPとpreviewは無効のままとする。

## 読出しと時点

- 既存の非公開`odds` RPCで履歴・as-ofを読む。
- `races` RPCは`normalize`、`history`、`day`を提供する。dayには`date=YYYYMMDD`と`at`を明示し、その時点までにD1で公開された最新の既観測断面だけを返す。
- 実際の投票締切と提供元更新時刻は未確認ならnull。予定発走から推定した締切を実測時刻に置き換えない。
- 結果・払戻の表示を保存するが、取消・返還を含む精算の適合を確認するまではPaper精算に流さない。結果欄が空でも発売中とはみなさない。
- 当日オッズの取得を続けても、直前の最後の更新を取得できたという保証にはならない。確定状態が未確認の断面を「最終」と決めない。月次FINAL_ONLYと判断入力の分離は維持する。

## 移行

収集DOと原本解析Workerは既存devへ配置済み。取得は無効、保存済み原本だけを読む解析Cronは有効。12個のローカルストアを非公開R2へアーカイブし、全ファイルのハッシュ一致を確認した。201オッズ観測の原本・取得証跡を検証してR2/D1へ登録し、レース情報2断面も移送した。解析はクラウド側で順次進める。アーカイブに含む元の`available_at`と、Cloudflareで再解析する際の新しい`available_at`を混ぜない。移行途中の原本はMacでも増えているため、完全移行やMac停止後の新規取得成功とはしない。

1. Cloudflareからの公式取得を確認する。現在の停止解除は自動承認審査で拒否されたため、単発診断についてユーザーの明示承認を待つ。
2. 複数時点の取得、R2/D1保存、解析、履歴の再読出しを実測する。
3. Macの既存データを、元の取得時刻・解析利用可能時刻・台帳を変えずに非公開のクラウドへ移す。クラウドで後から解析した版の利用可能時刻は移行後の実時計とする。
4. クラウド収集を確認後に、重複取得を避けてMacの有限収集を終了する。移行途中の欠測は残す。

新規登録・メール・問い合わせ送信は行わない。実データ・詳細出力はGit・CI・PRへ含めない。
